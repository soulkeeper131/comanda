# Ко Манда — пускане в продукция

Кратък списък какво трябва да е настроено на сървъра. Всичко тук е
задължително, освен изрично отбелязаното.

---

## 1. Променливи на средата

### Задължителни — без тях приложението не тръгва

| Променлива | Стойност |
|---|---|
| `SESSION_SECRET` | Минимум 32 знака. Генерирайте с командата отдолу. |

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Приложението **отказва да стартира** без нея — нарочно, за да не тръгне
никога с познат ключ.

### Задължителни при първо пускане

При празна база приложението създава три тестови акаунта, но **само ако**
паролите са зададени. Без тях seed-ът се пропуска и в лога излиза
предупреждение.

| Променлива | За кого |
|---|---|
| `SEED_ADMIN_PASSWORD` | `admin@komanda.bg` |
| `SEED_CLIENT_PASSWORD` | `client@komanda.bg` |
| `SEED_INSPECTOR_PASSWORD` | `inspector@komanda.bg` |

Няма пароли по подразбиране. По-рано тук стоеше `admin1234` — ако
променливата липсваше, продукцията тръгваше с публично известна админска
парола. Празната база е по-безопасна от слабата.

### По желание

| Променлива | Какво прави |
|---|---|
| `NEXT_PUBLIC_APP_URL` | Базов адрес за връзките в имейлите |
| `BACKUP_DIR` | Къде отиват резервните копия (виж §2) |
| `BACKUP_KEEP` | Колко копия се пазят (по подразбиране 7) |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Плащания |
| `SMTP_*`, `NOTIFY_EMAIL` | Имейли (може и от админския панел) |
| `VAPID_*` | Push известия |

## 2. Резервно копие — задължително

**Без това пускането е рисково.** При 10–50 плащащи клиента загубена база
значи загубени абонаменти, история на обходите и всички снимки.

### Cron в Coolify

```
0 2 * * * /app/scripts/backup-db.sh
```

Всяка нощ в 2:00. Архивът съдържа базата **и** снимките.

### Копията да са извън тома на базата

По подразбиране отиват в `data/backups/` — на същия том като базата.
Загуби ли се томът, копията отиват с него. Задайте:

```
BACKUP_DIR=/backups
```

и монтирайте `/backups` към друго място.

### Проверка, че копие се възстановява

Непроверено копие не е копие. Веднъж след настройката:

```bash
npm run db:backup                    # прави копие
npm run db:restore                   # показва наличните
bash scripts/restore-db.sh <архив> --check   # проверява, без да пипа нищо
```

При реална авария:

```bash
bash scripts/restore-db.sh <архив> --yes
```

Преди презаписване скриптът запазва текущата база.

## 3. Една инстанция

SQLite е един файл. Coolify **не бива** да е конфигуриран с повече от една
реплика — иначе две инстанции пишат в един файл.

Rate limiting също е в паметта и работи само при една инстанция.

При 10–50 клиента това е напълно достатъчно.

---

## 4. Постоянен том

`/app/data` трябва да е на постоянен том. Там са:

- `sqlite.db` — базата
- `photos/` — снимковите доказателства
- `backups/` — копията (ако не е зададен `BACKUP_DIR`)

Без постоянен том всичко изчезва при всеки деплой.

## 5. Проверка след деплой

```bash
curl -i https://comanda.blv.bg/                 # 200
curl -i https://comanda.blv.bg/api/me           # 401 без сесия
```

В лога трябва да пише:

```
[db] Миграциите са приложени (или вече бяха).
```

Ако видите `[db] Seed при старт ПРОПУСНАТ` — липсват `SEED_*` променливите.
